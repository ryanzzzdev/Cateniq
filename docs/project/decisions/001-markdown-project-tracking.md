# 001 — Markdown project tracking

Date: 2026-10-22

Status: Accepted

## Context

The user requested Voltix's agent rules, documentation method and engineering standards before establishing Cateniq's implementation plan. The repository and GitHub remote already exist; existing concept and discussion files must be preserved.

## Decision

Adapt Voltix's root AGENTS instructions, documentation guide and repository-carried project-management skill. Canonical records live in `docs/project/`: one backlog using sequential CAT IDs, a milestone roadmap, architecture, feature contracts, numbered decisions, blockers, evidence when available and monthly UTC journals with separate LLM-model and coding-agent attribution.

Cateniq owns its records independently. The existing concept retains motivation and portfolio context; current implementation details belong in canonical records. Preserve all discussions as background, not instruction or automatic acceptance. Record related documentation with its implementation in the same commit when committing is authorised.

## Alternatives

External issue tracking is unnecessary for this initial project. Copying Voltix's technical milestones or completed statuses would misrepresent Cateniq. Machine-local-only skills would not travel with a clone.

## Consequences and follow-up

Meaningful work includes record closeout without another reminder. Do not create duplicate trackers, empty evidence or repetitive journal entries. This workflow does not authorise commits, pushes, publication or automation. Inspect repository state each session.

## Acceptance source

Explicit user request on 2026-10-22 to use Voltix's rules and project-management standards. CAT IDs and Cateniq paths are routine adaptations within that authority.
